# UI Rules

NP-Next uses:
- Next.js
- React
- TypeScript
- Tailwind CSS
- shadcn/ui

Visual direction:
- enterprise operations dashboard
- clean and restrained
- information-dense but readable
- accessible
- light/dark ready
- minimal decoration

Forbidden:
- Neo Brutalism
- Material UI
- Chakra UI
- Ant Design
- Bootstrap
- another component framework

Component policy:
1. Reuse existing project components.
2. Check shadcn/ui before creating custom primitives.
3. Prefer composition of shadcn primitives over bespoke component systems.

Async UI must cover loading, empty, error, success, disabled, and retry states as appropriate.

Data-heavy screens must support search/filter/pagination instead of rendering 95+ distributors as a wall of cards.

Operational controls such as Run/Cancel/Enable/Disable/Delete must make state and consequence explicit and prevent duplicate submission.

UI must not contain credentials, Playwright logic, or business comparison formulas. Browser code talks to FastAPI.
